## 🚀 Git Commit Message Convention (Lite Version)

본 문서는 프로젝트 참여자에게 적용되는 **Commit Message Convention** 가이드라인입니다.
개발 생산성을 위해 **기준을 완화**하여 운영하지만, 최소한의 가독성과 규칙은 준수해야 합니다.

---

### 1. 📋 Commit 메시지 구조

커밋 메시지는 **제목(Subject)**이 필수이며, **본문(Body)**은 선택 사항입니다.

`[TYPE] 설명 (제목은 필수)

(한 줄 띄우기)

- 본문 내용은 선택 사항입니다.
- 단, 본문을 작성할 경우 반드시 Bullet Point(-)를 사용해야 합니다.`

---

### 2. 📝 제목 (Subject) 규칙

제목은 반드시 **`[TYPE] 설명`** 형식을 따라야 합니다.

| TYPE         | 설명                                        |
| :----------- | :------------------------------------------ |
| **ADD**      | 신규 기능 및 파일 추가                      |
| **UPDATE**   | 기존 기능 개선, 업데이트, 수정              |
| **FIX**      | 버그 수정                                   |
| **DELETE**   | 기능 또는 코드 삭제                         |
| **REFACTOR** | 코드 구조 개선 (기능 변경 없음)             |
| **TEST**     | 테스트 코드 관련                            |
| **DOCS**     | 문서 수정 (README 등)                       |
| **CHORE**    | 빌드 설정, 패키지 매니저 설정 등 자잘한작업 |

> **작성 예시:**
>
> - `[ADD] 로그인 페이지 퍼블리싱`
> - `[FIX] 토큰 만료 시 무한 로딩 버그 수정`

---

### 3. 📄 본문 (Body) 규칙 (선택 사항)

본문 작성은 **선택 사항**입니다. 단순한 수정의 경우 제목만 작성해도 무방합니다.
하지만 본문을 작성하기로 결정했다면, **다음 규칙을 엄격히 따라야 합니다.**

1.  **형식:** 반드시 **Bullet Point (`- `)**로 시작해야 합니다.
2.  **내용:** 제목에 다 담지 못한 상세 구현 내용이나 이유를 적습니다.

> **올바른 예시 (본문 포함 시):**
>
> ```text
> [UPDATE] 결제 모듈 API 버전 변경
>
> - 기존 v1 API 지원 종료로 인한 v2 마이그레이션
> - 결제 검증 로직 추가
> ```

> **잘못된 예시 (본문 형식 위반):**
>
> ```text
> [UPDATE] 결제 모듈 API 버전 변경
>
> 그냥 v2로 바꿨음. (X -> Bullet Point 누락)
> ```

---

### 4. ⚙️ 자동 검증 시스템 (CI)

`feat/**` 브랜치에 `push` 할 때 GitHub Actions가 커밋 메시지를 자동으로 검사합니다.

#### 4.1. 검증 통과 조건

1.  **제목:** `[TYPE]` 키워드로 시작해야 합니다.
2.  **본문:**
    - 본문이 **없으면** → **통과 (Pass)**
    - 본문이 **있으면** → 줄마다 **`-` 로 시작하는지 검사 (형식 안 맞으면 Fail)**

#### 4.2. 검증 실패 시 해결 방법

커밋 메시지 수정 후 강제 푸시를 수행해야 합니다.

```bash
# 1. 메시지 수정 (대화형 에디터)
git commit --amend

# 2. 원격 저장소 덮어쓰기
git push --force
```
