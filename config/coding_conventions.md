## 🛡️ Checkstyle 코드 컨벤션 가이드라인

제시해 주신 XML 설정 파일은 자바(Java) 코드의 스타일 및 품질을 검사하는 도구인 **Checkstyle**의 설정 내용입니다. 이 설정을 바탕으로 팀원들이 코딩 표준을 쉽게 이해하고 준수할 수 있도록 가이드라인을 정리했습니다.

---

### 1. ⚙️ 파일 및 문자 인코딩 설정

| 항목            | 규칙                | 설정 값/모듈                               |
| :-------------- | :------------------ | :----------------------------------------- |
| **파일 인코딩** | `charset`           | **UTF-8**                                  |
| **파일 이름**   | `OuterTypeFilename` | 클래스 이름과 파일 이름이 일치해야 합니다. |

---

### 2. 📏 포맷팅 및 들여쓰기 규칙

| 항목                   | Checkstyle Module | 설정 값                   |
| :--------------------- | :---------------- | :------------------------ |
| **들여쓰기 (기본)**    | `Indentation`     | **4칸** (`basicOffset=4`) |
| **`case` 문 들여쓰기** | `Indentation`     | **4칸** (`caseIndent=4`)  |
| **라인 길이 제한**     | `LineLength`      | **120자** (`max=120`)     |

> 💡 **주요 사항:** 한 줄의 코드는 최대 **120자**를 넘지 않도록 유지해야 합니다.

---

### 3. 📛 네이밍 규칙 (Naming Convention)

변수, 메서드, 파라미터 이름에 대한 기본적인 자바 네이밍 규칙을 강제합니다.

| 항목            | Checkstyle Module   | 규칙                                                    |
| :-------------- | :------------------ | :------------------------------------------------------ |
| **메서드 이름** | `MethodName`        | 메서드 이름은 **`camelCase`**를 따라야 합니다.          |
| **지역 변수**   | `LocalVariableName` | 지역 변수 이름은 **`camelCase`**를 따라야 합니다.       |
| **파라미터**    | `ParameterName`     | 메서드 파라미터 이름은 **`camelCase`**를 따라야 합니다. |

---

### 4. 🧱 구조 및 기타 규칙

| 항목            | Checkstyle Module | 규칙                                                                                                |
| :-------------- | :---------------- | :-------------------------------------------------------------------------------------------------- |
| **중괄호 사용** | `NeedBraces`      | `if`, `for`, `while`, `do` 등의 제어문은 내용이 한 줄이라도 **항상 중괄호 `{}`**를 사용해야 합니다. |
| **Import 정리** | `UnusedImports`   | 코드에서 **사용하지 않는 `import` 문**은 반드시 제거해야 합니다.                                    |

---

### 📝 이 컨벤션의 목적

- **코드 일관성:** 모든 팀원의 코드가 동일한 형식과 스타일을 유지하도록 보장합니다.
- **가독성 향상:** 표준화된 들여쓰기 및 길이 제한을 통해 코드를 더 쉽게 읽고 이해할 수 있습니다.
- **오류 방지:** 불필요한 `import` 제거 및 중괄호 의무화 등을 통해 잠재적인 오류를 줄입니다.
